# نظام كاشير الملابس — نسخة موقع ويب (HTML / CSS / JS)

موقع ثابت بالكامل بدون خادم ولا قاعدة بيانات خارجية. كل البيانات تُحفظ داخل المتصفح (IndexedDB) ويعمل دون اتصال بعد أول زيارة.

## التشغيل
- محلياً: افتح `index.html` مباشرة، أو شغّل `python3 -m http.server` داخل المجلد ثم افتح http://localhost:8000
- على الإنترنت: ارفع كل الملفات إلى أي استضافة ثابتة (GitHub Pages، Netlify، Cloudflare Pages…). يلزم HTTPS لتثبيت التطبيق وللكاميرا.
- أول مرة: تظهر شاشة إعداد لإنشاء حساب المدير (admin) واسم المحل.

## الملفات
| ملف | وظيفته |
|---|---|
| index.html / style.css | الصفحة والتنسيق (وضع ليلي تلقائي أو يدوي) |
| app.js | الواجهة: البيع، المنتجات، الباركود، المخزون، الفواتير، الزبائن، المصاريف، التقارير، المستخدمون، الإعدادات |
| db.js | بديل الخادم: نفس مسارات API لكن داخل المتصفح، مع الصلاحيات والتراجع الذرّي عند الأخطاء |
| barcode.js | رسم باركود Code128 |
| sw.js / manifest.json | العمل دون اتصال وتثبيت التطبيق |
| test_db.js | `node test_db.js` اختبار المنطق (مترجم من test_api.py) |
| ui_smoke.py | اختبار واجهة بمتصفح آلي (Playwright) |

## ما أُضيف على النسخة القديمة
شاشة إعداد أولي، لوحة رئيسية (مبيعات اليوم + رسم 7 أيام + الأكثر مبيعاً + المخزون المنخفض)، تعليق الفواتير واسترجاعها، وضع ليلي، تصدير CSV (المنتجات، الفواتير، التقارير)، نسخ احتياطي واسترجاع بملف JSON، اختصارات (F2 للبحث، F9 لإتمام البيع).

## مهم
- البيانات على **هذا الجهاز وهذا المتصفح فقط**. لا تتزامن بين جهازين. نزّل نسخة احتياطية من الإعدادات بشكل دوري، وانقلها بين الأجهزة بالاسترجاع.
- مسح بيانات الموقع من المتصفح يحذف كل شيء، لذلك النسخة الاحتياطية ضرورية.
- الصلاحيات والمستخدمون تنظّم الواجهة فقط. من يملك الجهاز يستطيع الوصول لبيانات المتصفح، فلا تعتمد عليها كأمان صارم.
- لو تحتاج عدة أجهزة على قاعدة واحدة، استخدم النسخة القديمة (Flask) أو أضف خادماً لاحقاً؛ طبقة `db.js` مصممة لتُستبدل باستدعاءات fetch بنفس المسارات.
